# Edge B.R.O. — Backup & Restore Orchestrator

🇬🇧 [English](README.md) · [Usage Guide](README_USAGE.md) · 🇷🇺 [Русский](README_ru.md) · [Инструкция](README_USAGE_ru.md)

Централизованная система управления бэкапами и восстановления для парков edge-устройств на базе Debian. Полностью контейнеризована. Запускается одной командой `docker compose up`.

---

Семь контейнеров в `docker-compose.yml`:

| Сервис | Назначение |
|--------|-----------|
| **frontend** | React SPA за Nginx. Панель управления с поддержкой тёмной и светлой тем. Вкладки: Fleet, Flasher, Архив, Расписание, Логи, Настройки. Три языка (EN/RU/UK). Встроенная терминальная консоль для логов. |
| **backend** | FastAPI на Uvicorn. REST API, парсер IP (CIDR / диапазоны / списки), трекинг задач. Определяет физические и VPN IP хоста через `/host/proc/1/net/` (пропускает docker-мосты). |
| **worker** | Celery worker в привилегированном режиме. Запускает Ansible-плейбуки и команды разметки дисков. Требует доступ к `/dev` для прошивки. |
| **beat** | Планировщик Celery Beat. Запускает `borg prune` ежедневно в 03:00, применяет политики хранения. |
| **borg-server** | Изолированный SSH-сервер на порту 12345. Центральный Borg-репозиторий. Ключи узлов попадают в `authorized_keys` под `borg serve --restrict-to-path`. |
| **db** | PostgreSQL 15. Инвентаризация, история, группы, настройки, учётные записи. |
| **redis** | Redis 7. Брокер задач + хранилище результатов Celery. |

## Основные возможности

### Управление парком (Fleet)
- Регистрация узлов по IP-спискам, диапазонам (`192.168.1.50-60`) или CIDR-блокам (`10.0.0.0/24`).
- Параллельный bootstrap через Celery — до 24 узлов одновременно.
- Установка пакетов, инъекция SSH-ключей, сбор информации об оборудовании — всё через Ansible.

### Подготовка дисков (Auto-Prepare)
- Присваивает постоянные метки файловым системам: `edgeroot`, `edgeboot`, `edgelog`, `edgestor`, `EFI`.
- Сохраняет уникальный UUID FAT32-раздела EFI для последующего восстановления.
- Перезаписывает `/etc/fstab` с монтированием по `LABEL=` — защита от смены `/dev/sda` ↔ `/dev/nvme0n1`.

### Бэкапы и дедупликация
- Push-модель: оркестратор подключается к узлу по SSH, запускает `borg create`, данные стримятся в центральный репозиторий.
- **SSH keepalive** настраивается через `.env` (`SSH_KEEPALIVE_INTERVAL`, `SSH_KEEPALIVE_COUNT`).
- **Лимиты ресурсов** для каждой группы бэкапов:
  - Ограничение скорости (KiB/s)
  - Ограничение CPU (0–400% от ядра, через `systemd-run --scope`)
  - Выбор алгоритма сжатия (`lz4`, `zstd:1`–`zstd:9`)
  - Интервал чекпоинтов — авторасчёт по скорости канала или ручная настройка
- **Сквозная дедупликация**: все узлы хранятся в одном Borg-репозитории. Идентичные файлы ОС записываются единожды.
  - 1-й узел: экономия 55–65% (сжатие ~6 ГБ → ~2.5 ГБ)
  - Каждый клон добавляет лишь ~100–200 МБ
  - Инкрементные запуски: ~100–200 МБ уникальных данных
- **Умный планировщик очереди**:
  - Динамическое масштабирование параллельности при нехватке времени окна
  - Автоограничение параллельности по полосе пропускания (≥ 2 MiB/s на поток)
  - FIFO-очередь с временными сдвигами; слоты освобождаются мгновенно
  - Защита выполняющихся бэкапов после закрытия окна
- **Ротация**: по интервалам, по количеству или по временному окну. Глобально или с переопределением для группы. Запуск ежедневно в 03:00 через Celery Beat, затем автоматический `borg compact`.
- **Исключения**: настраиваются в UI. По умолчанию:

  | Шаблон | Назначение |
  |--------|-----------|
  | `/dev/*` | Системные устройства |
  | `/proc/*` | Виртуальная ФС процессов |
  | `/sys/*` | Информация sysfs |
  | `/run/*` | Временные файлы рантайма |
  | `/mnt/*` | Примонтированные ФС |
  | `/media/*` | Съёмные носители |
  | `/lost+found` | Восстановленные фрагменты |
  | `/var/log/edge/*` | Логи приложения Edge |
  | `/var/opt/edge/blobstore/*` | Локальное медиахранилище |
  | `/var/spool/edge/*` | Спул-директория Edge |
  | `/var/log/journal/*` | Логи systemd journal |
  | `/var/log/**/*.gz` | Сжатые ротированные логи |
  | `/var/log/**/*.1` | Ротированные лог-файлы |
  | `/var/hasplm/*` | Данные лицензирования Sentinel HASP |
  | `/etc/hasplm/*` | Конфигурация Sentinel HASP |

### Восстановление на железо (Flasher)
- Подключаете диск через USB-SATA/NVMe переходник → выбираете узел + снимок → прошиваете.
- Системный диск самого сервера отфильтрован и защищён.
- **Кросс-миграция**: NVMe ↔ SATA работает бесшовно (fstab по меткам).
- Разметка GPT, восстановление EFI UUID, `borg extract`, chroot + GRUB, пересборка initramfs.
- Сброс сети: удаление persistent-net, инъекция DHCP для `eth*`/`en*`.
- Пакеты Sentinel HASP восстанавливаются из локального кэша при отсутствии интернета.
- Сервис проверки связи после восстановления обновляет статус узла до `RESTORED`.

### Live-CD клиент (киоск)
- Компилирует загрузочный Debian Live ISO на лету со встроенными IP оркестратора и токеном авторизации.
- **Основной сценарий использования**: Запуск на ПК/ноутбуке технического специалиста (например, в офисе). Клиент может прошивать целевые диски напрямую по сети (скачивая резервные копии с облака/сервера) или работать в полностью автономном режиме, предварительно синхронизировав нужные бэкапы на свободное место загрузочной флешки.
- **Вторичный сценарий**: Также поддерживается запуск Live-USB непосредственно на целевом edge-узле.
- **Синхронизация одного снимка**: генерирует временный mini-репозиторий через конвейер `borg export-tar` | `borg import-tar` — не нужно качать всю историю.
- Отображение скорости, прогресс-бар и ETA в реальном времени.
- **Управление киосками**: регистрация, подтверждение, блокировка, перепривязка из панели. Динамические ключи сопряжения.

### Интеграция с WireGuard VPN
- QR-сканер через веб-камеру (`jsQR`) для конфигов WireGuard, с ручной вставкой в качестве запасного варианта.
- VPN-профили сохраняются на USB в `/media/usb-data` с правами `0600 root:root`.
- Эндпоинты бэкенда: статистика туннеля (`wg show`), перезагрузка NM, up/down.

### Лицензирование Sentinel LDK
- Автоматическое определение `hasp_runtime_version` при bootstrap.
- Статусы лицензий в реальном времени: Active / Expired / Clone Detected / Disabled.
- Скачивание C2V-отпечатков через SSH (`hasp_update lf` + `hasp_update i`), с fallback на ACC API.
- Загрузка V2C-обновлений: drag-and-drop в дашборде, применение удалённо по SSH.

## Системные требования

### Сервер оркестратора
| Ресурс | Минимум | Рекомендуется |
|--------|---------|--------------|
| CPU | 2 ядра (x86_64) | 4 ядра |
| RAM | 4 ГБ | 8 ГБ |
| Сеть | 100 Мбит/с | 1 Гбит/с |
| Системный диск | 20 ГБ свободно | — |
| Том для бэкапов | По размеру парка — см. ниже | Выделенный диск |

**Расчёт тома для бэкапов** (квартальные бэкапы, хранение 5 последних = ~1.25 года). При достаточном количестве идентичного оборудования сквозная дедупликация Borg работает значительно эффективнее:

| Размер парка | Оценка (Разнородный парк) | Оценка (Идентичное оборудование) |
|-------------|---------------------------|----------------------------------|
| 50 устройств | ~60 ГБ | ~40 ГБ |
| 300 устройств | ~300 ГБ | ~150–200 ГБ |
| 1000 устройств | ~1 ТБ | ~500–600 ГБ |

### Edge-узел (киоск-ПК)
- 64-бит x86 CPU, 2 ГБ RAM (рекомендуется 4 ГБ), Ethernet или Wi-Fi.

### USB-накопитель для прошивки
- Минимум 32 ГБ (лучше больше), скорость записи ≥ 15-20 МБ/с. Рекомендуется флешка уровня Netac US5 и выше.

## Стабильность USB-оборудования

USB-переходники с UAS-драйверами (например, JMicron `152d:0581`) могут зависать при интенсивной записи `borg extract`. Принудительно переключите на стабильный legacy-драйвер `usb-storage`:

```bash
echo -e "options usb-storage quirks=152d:0581:u\noptions uas quirks=152d:0581:u" \
  | sudo tee /etc/modprobe.d/usb-quirks.conf
sudo usbreset 152d:0581   # или переподключите USB-кабель
```

Замените `152d:0581` на Vendor:Product ID вашего переходника из `lsusb`.

## Безопасность и авторизация

- **Авторизация**: логин + пароль, сессии через HTTP-only JWT-куки (`admin_session`).
- **Роли**:
  - **Superadmin** — управляет учётными записями (Настройки → Пользователи).
  - **Admin** — работает с системой, но не может управлять пользователями.
- **Авторизация киосков**: сопряжённые Live-CD используют заголовок `Authorization: Bearer <token>`. Offline-ISO поддерживают `?token=` в URL.
- **Первый запуск**: суперадмин создаётся из значений `.env` (`SUPERADMIN_USERNAME`, `ADMIN_PASSWORD`). Создаётся однократно — изменения `.env` не перезаписывают пароль, изменённый через UI. Для сброса: очистите таблицу `users` или обновите `.env` + перезапуск.

## Что оркестратор меняет на целевых узлах

Никаких агентов не устанавливается. Все действия одноразовые, через SSH.

### Bootstrap (первичная подготовка)
| Действие | Детали |
|----------|--------|
| APT-пакеты | `python3`, `python3-pip`, `borgbackup`, `parted`, `e2fsprogs`, `dosfstools`, `util-linux` |
| SSH-ключ | Ed25519 pubkey оркестратора → `/root/.ssh/authorized_keys` |
| sshd_config | `PermitRootLogin prohibit-password` |
| Пользователь borg | Системный пользователь с SSH-ключами в `/home/borg/.ssh/` |
| Обход прокси | APT-прокси временно переименовываются в `*.disabled`, восстанавливаются после |

### Auto-Prepare (метки дисков)
| Действие | Детали |
|----------|--------|
| Метки разделов | `edgeroot`, `edgeboot`, `edgelog`, `edgestor`, `EFI` через `e2label`/`fatlabel` |
| `/etc/fstab` | Заменяется шаблоном по меткам. Резервная копия: `/etc/fstab.bak` |
| Загрузчик | `update-grub` + `update-initramfs -u` |

### Выполнение бэкапа
| Действие | Детали |
|----------|--------|
| Файлы на узле | **Не изменяются** — `borg create` работает в режиме только чтения |
| Процессы | Временные `borg create` + `ssh` туннель, завершаются по окончании |
| CPU/IO контроль | Опционально `systemd-run --scope -p CPUQuota=... -p IOSchedulingClass=idle` |
