# Direct dependencies, pinned exactly.
#
# These were floors (`>=`) with no lockfile, which meant every `docker compose
# build` resolved whatever was newest that day. The local virtualenv the test
# suite runs in and the container serving the fleet had drifted several major
# versions apart -- Starlette 0.36 against 1.6, redis-py 5.0 against 8.1 --
# so a green test run said nothing about what was actually deployed. It also
# let bcrypt cross a major boundary unannounced and change how it handles
# over-long passwords.
#
# Transitive dependencies are pinned separately in requirements.lock, which is
# what the image installs. Change a version here, then regenerate the lock:
#
#     pip install -r requirements.txt && pip freeze > requirements.lock
#
# Run that on Python 3.13 -- the version in docker/backend/Dockerfile -- since
# a freeze taken on a different interpreter records different markers.
